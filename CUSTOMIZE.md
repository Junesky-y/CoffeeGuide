# Налаштування сайту

## 1. Як змінити назву сайту

Назва зберігається в **одному місці** для кожної мови — в ресурсних файлах:

| Файл | Ключ | Що змінити |
|---|---|---|
| `Resources/SharedResource.uk.resx` | `App_Name` | Українська назва |
| `Resources/SharedResource.en.resx` | `App_Name` | Англійська назва |

Ця назва автоматично потрапляє в шапку сайту, заголовок вкладки браузера та підвал.

Інші тексти, які ви, можливо, захочете змінити, лежать у тих самих файлах:
- `Home_Title` та `Home_Lead` — заголовок і вступ на головній сторінці;
- `Home_Culture_Title` та `Home_Culture_Text` — блок про кавову культуру;
- `Footer_Text` — текст підвалу (`{0}` — рік, `{1}` — назва сайту).

Як редагувати: відкрийте `.resx` у Visual Studio (таблиця «Name / Value») або як звичайний текстовий файл,
змініть вміст тегу `<value>`, збережіть і перезапустіть застосунок (`Ctrl+C`, потім `dotnet run`).

Назву проєкту (`CoffeeGuide`), папки й простори імен у коді **змінювати не потрібно**: це внутрішнє ім'я, його не бачить користувач.

Логотип у шапці та іконка вкладки: `wwwroot/images/logo.svg` і `wwwroot/favicon.svg`. Їх можна замінити своїми файлами
з тими самими назвами.

## 2. Як додати фото замість заглушок

Див. **IMAGES.md**: для кожного запису вже прописано назву файлу (наприклад, `wwwroot/images/recipes/latte.jpg`).
Достатньо покласти файл із такою назвою й перезапустити застосунок.

## 3. Як додати нове зерно, молоко, сироп, спосіб приготування або рецепт

1. Відкрийте відповідний файл у `Data/Json/uk` і додайте новий об'єкт у кінець списку (дивіться сусідні записи як зразок).
2. Додайте такий самий запис в `Data/Json/en` з **тими самими `id` та `slug`**.
3. Для фото: у полі `imagePath` вкажіть `/images/<папка>/<slug>.jpg` і покладіть файл у `wwwroot/images/<папка>/`.
4. Якщо рецепт використовує новий інгредієнт, спочатку додайте його в `ingredients.json` (обидві мови).
5. Перезапустіть застосунок. Запис з'явиться в каталозі, пошуку та відкриється у модальному вікні.

Правила: `id` — унікальне число, `slug` — унікальний латиницею; значення enum (`category`, `roastLevel`) пишуться
англійськими ключами; необов'язкові поля можна ставити в `null`. Помилки (дублікати, неіснуючі посилання)
виводяться в консоль при запуску.

## 4. Перевірка на телефоні

- **У браузері комп'ютера:** F12 → іконка пристроїв (`Ctrl+Shift+M`) → оберіть, наприклад, iPhone 12 або Pixel 7.
- **На справжньому телефоні** (комп'ютер і телефон в одній Wi-Fi мережі):
  1. Запустіть `dotnet run --urls "http://0.0.0.0:5080"`.
  2. Дізнайтеся IP комп'ютера (`ipconfig` у Windows, рядок IPv4).
  3. У браузері телефона відкрийте `http://<IP>:5080`.
  4. Якщо сторінка не відкривається, дозвольте порт 5080 у брандмауері Windows.

Що враховано для телефонів:
- верхня шапка закріплена й завжди видима при прокручуванні; бургер-меню праворуч;
- перемикач мови знаходиться всередині меню (на комп'ютері — справа в рядку меню);
- якщо назва сайту не вміщається в шапці, там лишається лише логотип, а назва показується зверху розкритого меню;
  це працює автоматично для будь-якої довжини назви (див. розділ 1);
- панель фільтрів, що згортається; картки з обмеженим описом; модальне вікно на весь екран;
- кнопки не менші за 44 px, поля вводу 16 px (iOS не збільшує сторінку), відступи під «чубчик» і системні панелі;
- автофокус пошуку вимкнено на сенсорних екранах.
