# Посібник зі створення кави (Coffee Encyclopedia & Brewing Guide)

Інформаційний вебзастосунок на ASP.NET Core Razor Pages: енциклопедія кавових зерен, молока, сиропів,
способів приготування та рецептів. Контент зберігається в локалізованих JSON-файлах (українська та англійська).

## Запуск

Потрібен .NET SDK (перевірка: `dotnet --version`).

```bash
cd CoffeeGuide
dotnet run
```

Відкрийте в браузері адресу, яку покаже консоль (наприклад `https://localhost:7xxx`).
Якщо браузер скаржиться на сертифікат: `dotnet dev-certs https --trust`.

## Архітектура

| Шар | Папка | Відповідальність |
|---|---|---|
| Моделі | `Models/` | Класи предметної області та enum (`CoffeeBean`, `CoffeeRecipe`, `RoastLevel` тощо) |
| Дані | `Data/` | `ContentStore` читає JSON, перевіряє, зв'язує сутності, кешує по мовах; `Data/Json/uk`, `Data/Json/en` — сам контент |
| Сервіси | `Services/` | Отримання, пошук і фільтрація (`ICoffeeRecipeService` та ін.). Не знають про HTML |
| ViewModels | `ViewModels/` | Картки (`CardViewModel`), універсальна модель модального вікна (`DetailsDto`), `DetailsFactory` |
| Сторінки | `Pages/` | Razor Pages: обробка запитів і відображення |
| Ресурси | `Resources/` | Тексти інтерфейсу (`.resx`) |
| Статика | `wwwroot/` | CSS, JavaScript, зображення |

Принцип: **моделі** описують структуру, **сервіси** віддають дані, **сторінки** лише показують.
Тексти енциклопедії є тільки в JSON; тексти інтерфейсу — тільки в `.resx`.

### Як працює модальне вікно
1. Сторінка будує картки зі списку моделей (`_ContentCard.cshtml`). Кнопка картки має `data-details-url`.
2. `wwwroot/js/details-modal.js` перехоплює клік і робить `fetch` до обробника, наприклад `GET /recipes?handler=Details&id=3`.
3. Сервер знаходить запис через сервіс, `DetailsFactory` перетворює його на `DetailsDto` (JSON).
4. Єдине вікно `_DetailsModal.cshtml` очищається й малює нові дані через `textContent`.
5. Відповіді кешуються в пам'яті сторінки, застарілі запити скасовуються (`AbortController`).
6. Посилання всередині вікна (наприклад «рекомендоване зерно») відкривають інший запис у цьому ж вікні.

### Локалізація
- Мова за замовчуванням — українська (`uk`), додаткова — англійська (`en`); обирається cookie через `/set-language`.
- Якщо запису або файлу немає в обраній мові, використовується українська (за Id). Помилок рендерингу немає.

## Як додати новий контент (без зміни коду)
1. Додайте запис у потрібний файл у **обох** папках `Data/Json/uk` і `Data/Json/en` з однаковими `id` та `slug`
   (`id` — унікальне число > 0).
2. Перезапустіть застосунок (`Ctrl+C`, `dotnet run`).
3. Запис автоматично з'явиться в каталозі, пошуку та відкриється в модальному вікні.

Значення enum пишуться англійськими ключами: `roastLevel` — `Light`, `Medium`, `MediumDark`, `Dark`;
молоко — `Animal`, `Plant`; сиропи — `Fruit`, `Nut`, `Spice`, `Sweet`, `Other`;
рецепти — `Black`, `MilkBased`, `Iced`, `Dessert`; інгредієнти — `Coffee`, `Milk`, `Syrup`, `Water`, `Sweetener`, `Topping`, `Other`.
Необов'язкові значення можна ставити в `null`: відповідна секція просто не показується.

Помилки в даних (дублікати, посилання на неіснуючі записи, відсутні зображення) пишуться в консоль із позначкою мови.
Некоректні записи пропускаються, застосунок не падає.

## Зображення
Для кожного запису вже прописано шлях `/images/<папка>/<slug>.jpg`. Покладіть фото з такою назвою в `wwwroot/images/<папка>/`
і перезапустіть застосунок: заглушка замінюється фото. Повний перелік назв, вимоги до файлів і поради: **IMAGES.md**.
Використовуйте лише фото з вільною ліцензією або власні; джерела вкажіть у `wwwroot/images/CREDITS.md`.

## Налаштування
Як змінити назву сайту, додати контент і перевірити мобільну версію: **CUSTOMIZE.md**.

## Відомі обмеження
- Після зміни JSON потрібен перезапуск (дані кешуються при старті).
- Фільтр за походженням і різновидом залежить від мови (значення беруться з поточної мови).
- `fatContentPercent` для молока не заповнено, бо джерело даних для точних значень не додано.
- Факти в контенті необхідно перевірити за надійними джерелами перед здачею.
